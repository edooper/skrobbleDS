Technical Overview · v0.95.6

SkrobbleDS

A Last.fm scrobbler for Linn DS and OpenHome-compliant UPnP network music players. It finds your player on the LAN, listens to what it plays, and submits each track to Last.fm — no cloud, no account linking on the device, just a small daemon on your network.

Python 3.8+ stdlib-only · Flask + waitress Web UI :9099 UPnP / SSDP discovery SQLite (WAL) Docker · host networking

01 — The signal path

How a played track becomes a scrobble

The whole system is one idea: a producer/consumer split decoupled by a singleton event bus. Players never call the scrobbler directly. They observe the hardware and emit events; the scrobbler consumes them and talks to Last.fm. Everything downstream hangs off that seam.

Failed submissions fall back to the SQLite scrobble_cache and are retried — queue-driven, plus a periodic drain every 300s. Nothing queued at shutdown is dropped.

02 — The map

Modules, and what each one owns

Pure Python. The top-level modules use PEP 8 snake_case; the self-contained Upnp/ control-point package keeps a legacy CamelCase style ported from the original project.

Entry · Orchestrator SkrobbleDs.py

Constructs every component, wires the event-bus logger, installs SIGTERM/SIGINT handlers, then blocks in webui.start(). Implements DiscoveryObserver: a discovered device becomes a Player, a departed one is shut down.

The seam EventBus.py

Singleton pub/sub. Copies its listener list before dispatch so callbacks run outside the lock. Two event types flow across it: now_playing and scrobble.

UPnP control point Upnp/

Self-contained SSDP + GENA implementation: Discovery, Device, EventServer, EventSub, Ssdp, HttpPacket, HttpConnection, NetUtil, Service. Only urn:linn-co-uk:device:Source:1 devices are discovered.

Producer Player.py

Wraps one device. Subscribes to Info + Playlist/Ds services (Cara av-openhome-org and Davaar linn-co-uk names). Debounced threading.Timers wait for metadata and confirm play status before emitting.

Consumer Scrobbler.py

Two queue.Queues drained by two daemon threads. Computes elapsed playtime tolerant of pauses/buffering, applies the scrobble rules, and routes failures to the cache. Only players in settings are scrobbled.

API client LastFm.py

Talks to ws.audioscrobbler.com via urllib. Config lazy-loads on first use. All authed calls MD5-signed. Auth flow: getToken → user authorizes → getSession → per-user session key.

Persistence Database.py

SQLite in WAL mode for concurrent scrobbler + web-UI access. Two tables: scrobble_cache (FIFO retry, BEGIN IMMEDIATE to avoid double-reads) and scrobble_history (pruned). Injected, not imported globally.

State Settings.py

Accounts, players, network interface, and a per-player → session-key map. Guarded by an RLock. Saves atomically (temp file + os.replace) and preserves the API credentials already in the file.

Interface WebUi.py

Flask application factory. All mutating routes are POST + CSRF-protected; optional basic auth via hmac.compare_digest. Served by waitress by default. Routes: /, /addAccount, /logs, /health, /exit.

Observability Logger.py

Thread-safe queue-drained logger. Keeps an in-memory ring buffer of recent lines (always available, independent of file logging) that the web UI surfaces.

Tuning Constants.py

Every threshold and timer lives here — scrobble rules, debounce delays, device type, log-buffer sizes. Change behavior here, never inline.

03 — Lifecycle

From discovery to decision

  1. Discover. Discovery sends M-SEARCH and listens for SSDP alive/byebye. Source devices are retrieved, described, and given per-device expiry timers.
  2. Subscribe. Each device becomes a Player that GENA-subscribes to its Info and Playlist/Ds services and starts receiving playback events.
  3. Parse & debounce. Incoming events drive a small state machine. DIDL-Lite metadata is parsed; debounced timers wait ~10s for metadata and play status to settle.
  4. Now playing. On confirmed play, the Player emits now_playing; the Scrobbler pushes a track.updateNowPlaying to Last.fm.
  5. Record timestamps. Playing/stopped timestamp pairs accumulate on the current track — the raw material for computing real elapsed playtime.
  6. Decide on stop. Shortly after a Stop, the Player emits scrobble. The Scrobbler tests the track against the rules below and submits — or caches for retry.

04 — The rules

When a track actually counts

These are Last.fm's scrobbling rules, encoded as constants. Elapsed playtime is computed by pairing playing/stopped timestamps, so pauses and buffering don't inflate the count.

30s
Minimum track duration. Anything shorter is never scrobbled.
SCROBBLE_MIN_DURATION
50%
Scrobble once playtime passes half the track's duration…
SCROBBLE_PERCENT_THRESHOLD
240s
…or once playtime passes four minutes, whichever comes first.
SCROBBLE_TIME_THRESHOLD
10s
Debounce delays: wait for metadata, confirm status, scrobble after Stop.
PLAYER_*_DELAY
The test, in one line: duration > 30s and ( playtime > 50% × duration or playtime > 240s ). Pass → submit and record to history. Fail the network, not the rule → cache and retry.

05 — Recently added

Activity Log & submission-failure callout

The web UI now surfaces what the daemon is doing without touching a shell. The Logger keeps an in-memory ring buffer; the page renders the last 10 lines and polls /logs every 5 seconds. When Last.fm rejects a submission, a red banner calls it out explicitly.

The buffer works whether or not file logging is enabled. The callout auto-clears once error lines scroll out of the 200-line window. Log lines render via textContent so a track name can never inject markup.

DOCKER & TESTS

# host networking is required for
# UPnP multicast discovery
docker-compose up -d

# pytest — repo root on sys.path
pytest
pytest tests/test_scrobbler.py
Why host networking? UPnP/SSDP discovery relies on multicast on the local segment. Bridged container networks don't forward it, so the container must share the host's network stack to see your players.

08 — Things to hold onto

Conventions & gotchas

Threading

Player state under an RLock, Settings under an RLock, the shared player list under list_mutex, the EventBus copies listeners before dispatch. Preserve these when editing.

Git hygiene

config/ is ignored except the example. Never commit config.json, skrobbleds.db, or skrobbleds.log.

Tuning

Scrobble thresholds and timer delays live in Constants.py. Change them there, not inline at the call site.

Two dialects

Service names come in both flavours — Cara urn:av-openhome-org:* and Davaar urn:linn-co-uk:*. Player handles both.

Naming styles

Upnp/ is legacy CamelCase; top-level modules are PEP 8. Match whichever area you're editing.

Clean shutdown

Shutdown enqueues a 'bye' sentinel after pending items, so queued scrobbles are submitted, never dropped.
